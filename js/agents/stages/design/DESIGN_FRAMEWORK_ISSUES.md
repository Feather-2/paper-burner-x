# Design 框架深度问题分析报告

在对 `js/agents/stages/design` 目录进行深度审计后，除了已识别的“风格锁”和“提示词中心化”问题外，该框架在工程落地和长程稳定性方面仍存在以下核心问题：

---

## 1. 结构化漏洞：基于正则的 DSL “外科手术”
**问题描述**：`VisualHandler` 和 `ImageGenerator` 大量使用正则表达式（如 `fillImagePlaceholders`）来查找和替换 `<div data-el="image-placeholder">`。
- **风险**：LLM 生成的 HTML 标签属性顺序、空格甚至极小的语法错误（如缺少引号）都会导致正则匹配失效。这会导致“视觉填充”阶段静默失败，最终交付给用户的 PPT 依然是占位符。
- **根因**：使用了字符串处理而非结构化的 DOM/AST 操作来维护 DSL 状态。

## 2. 反应逻辑：延迟的视觉反馈循环
**问题描述**：`SlideSubAgent` 的逻辑是“先生成 DSL -> 后提取视觉槽位”。
- **风险**：如果 LLM 生成的布局逻辑上不支持它自己声明的视觉需求（例如在一个 4:3 的区域塞入了 4 个 16:9 的图像槽位），系统只有在渲染阶段才会发现冲突。
- **根因**：缺乏“预研”阶段。理想状态下，布局意图（Wireframe Intent）应该在 DSL 文本生成之前被语义化地校验。

## 3. 视觉孤岛：资产生成的“盲目并行”
**问题描述**：`VisualSubAgent` 同时调用图像生成器和 SVG 生成器，但这两个生成器之间互不感知。
- **风险**：同一张幻灯片上可能出现极其写实的 AI 摄影图像和极其简陋的扁平化 SVG 图标，导致视觉一致性（Visual Harmony）断裂。
- **根因**：资产生成缺乏“跨模态样式对齐”上下文。资产生成应该是互知的，或至少共用一个更详细的视觉特征向量。

## 4. 预算机制的“价值盲区”
**问题描述**：`ImageGenerator` 的预算控制（Budget Control）主要基于 `priorityRank` 和 `maxCostUSD`，这是一种纯工程化的计数器逻辑。
- **风险**：系统无法区分“封面大图”失败和“第 30 页装饰图标”失败的严重程度。如果封面图因预算耗尽被 skip，整个作品的商业价值将归零。
- **根因**：预算分配缺乏“语义重要性（Semantic Significance）”模型。

## 5. 状态机的一致性风险 (Dual-Sync Ghost)
**问题描述**：`DesignAgentLoop` 维护着 `DesignBlackboard` 和 `DesignContext`，且存在大量 `_syncToShared` 操作。
- **风险**：在 `BatchRepairAgent` 等并发或后置修复环节中，由于原子操作不完善，可能出现“DSL 修复了但 Blackboard 里的 Slot 记录没更新”的幽灵状态。
- **根因**：状态同步依赖于手动调用，而非基于事件流或响应式系统的 SSOT（单一真理源）。

## 6. Refiner 的“语义衰减（Semantic Entropy）”
**问题描述**：`react-refiner` 依赖 LLM 观察渲染后的“视觉报告”来进行修正。
- **风险**：随着修正轮数的增加，Agent 容易陷入“头痛医头”的局部优化，为了修好一个布局像素而搞乱了整篇文案的逻辑。
- **根因**：Refinement 过程缺乏“逻辑守恒”约束。

---

## 建议改造成点 (Fix Map)

1. **引入轻量级 DOM 引擎**：在 Node 环境下使用 `linkedom` 或自定义的 DSL 解析器替代正则替换。
2. **前后端校验分层**：增加 `Pre-Visual Check` 阶段，在生成 DSL 前由一个决策模型确定视觉元素的物理约束。
3. **视觉特征向量共享**：在生成资产前，提取一个通用的“视觉基因库（Visual DNA）”，强制要求 SVG 和 Image 生成器同时遵守。
4. **动态价值预算**：将预算与 स्लाइड 的 Claim 重要程度挂钩，优先保证关键页面的高质量视觉呈现。
