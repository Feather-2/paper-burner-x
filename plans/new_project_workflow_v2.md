# PPT 创作工作流重构提案 v2 (Product Strategy)

## 1. 根本反思：为什么之前的设计不对？
- **功能层级混淆**：之前的设计（无论是网格还是标签）都试图把“功能选择”和“文件上传”放在同一个平面。
- **干扰而非引导**：标签页切换会隐藏关键信息（如已上传的文件），导致用户在切换模式时产生焦虑感。
- **视觉琐碎**：过多的 Tab 和卡片嵌套让界面看起来像个“后台管理系统”，而不是一个“创作引擎”。

## 2. 重新定义：以“内容为王”的线性逻辑
**核心思想**：先提供“原材料”，再选择“加工厂”。

### 步骤一：投喂 (The Feed) —— `Step 1` 的主要职责
无论哪种模式，用户大都需要“传文件”或“说需求”。我们把这合并成一个超大的**灵感投喂区**：
- **左侧**：已有的素材库（侧边栏）。
- **中心**：一个巨大的交互区域，支持：
    1.  **文件拖拽**（最直观）。
    2.  **粘贴文字/大纲**（最快捷）。
    3.  **对话输入**（最自然，由 AI 自动判断属于哪种模式）。

### 步骤二：定策 (The Strategy) —— `Step 2` 的进化
当用户传完东西点击“下一步”时，才出现**模式决策**。此时，界面应当根据用户上传的东西，**智能推荐**模式：
- 上传了代码包？ -> **推荐：CodeSearch 源码分析**。
- 只有两句简单的想法？ -> **推荐：DeepSearch 深度调研**。
- 上传了详实的大纲？ -> **推荐：结构化速成**。
- 上传了 .pptx？ -> **直接进入修改流程**。

---

## 3. UI 表现形式重构 (Visual Direction)

### 3.1 `Step 1` (The Hub)
- 顶部保留极简标题：“开始你的创作”。
- 中间一个通透的容器，左侧是文件列表。
- 右侧不再是小卡片，而是一个**多态输入框**：
    - 顶部一排极简 Icon (上传、粘贴、链接、历史)。
    - 下方是巨大的文本域，文字提示：“告诉 AI 你的想法，或者直接把文件扔进来”。
- **这种设计极其节省垂直空间**，因为它只有一个核心交互点。

### 3.2 `Step 2` (The Config)
- 这里才是意图决策地。采用三个横向或垂直的“高级模式卡片”。
- 增强视觉仪式感：DeepSearch 带有动态雷达效果，CodeSearch 带有代码流效果。
